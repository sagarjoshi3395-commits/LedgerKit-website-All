Therefore the corrected preview value did NOT propagate; prod almost certainly still holds the original (incorrect) value. ## Question 3 — Do the delivery PDFs resolve on the live domain (expect 200)?

Probed against the live site (https://ledgerkit-deploy.emergent.host):
- `/downloads/diseases-reference-book.pdf`      → 200, content_type application/pdf, body starts `%PDF-1.7` ✓ REAL PDF
- `/downloads/medicine-reference-guide.pdf`     → 200, content_type application/pdf, body starts `%PDF-1.7` ✓ REAL PDF
- `/downloads/business-bookkeeping-system.pdf`  → 200 BUT content_type text/html, body is the SPA index.html shell ✗ **FILE MISSING**

The third is a FALSE 200: the Cloudflare frontend worker falls back to `index.html` (SPA `try_files` behavior) for any path not present in R2. So the bookkeeping-product PDF is NOT in the production frontend build/R2 — a buyer clicking that link gets an HTML page, not the PDF. (Note: preview verified the bookkeeping product "delivers PDF links" — but the asset itself is absent from the prod build.)

## Root cause
1. Production `EMERGENT_EMAIL_KEY` is (with high confidence) still the pre-correction value because redeploys never overwrite existing secret values — so prod email calls fail/auth-mismatch while preview works.
2. `business-bookkeeping-system.pdf` is missing from the production frontend build, so even with email fixed, the bookkeeping product's download link would 404-as-SPA.

## Fixes
- **User (secrets):** In Deployment Panel → Secrets, set `EMERGENT_EMAIL_KEY` to the correct `ek_...` email key (the same value verified in preview). Editing the value in the UI is the ONLY way to change an existing prod secret — a redeploy will NOT overwrite it. While there, confirm `EMAIL_FROM_NAME=LedgerKit` and `EMAIL_REPLY_TO=ledgerkitsupport@gmail.com`. Save, then redeploy for it to take effect.
- **Code (E1):** Add `business-bookkeeping-system.pdf` to the frontend's static downloads (e.g. frontend/public/downloads/) so it ships in the build and lands in R2, then redeploy. The other two PDFs are already present and correct.
